# Go Event-Driven Order Processing

Практический пример **event-driven микросервисной архитектуры на Go** для обработки заказов через gRPC и Kafka с использованием Redis и Docker.

Проект можно использовать как учебный стенд и reference implementation, чтобы разобраться, **как отдельные сервисы взаимодействуют между собой, как организовать асинхронную обработку событий и как собрать всё необходимое окружение в Docker**.

## Что можно получить из этого проекта

Изучая и запуская проект, вы сможете на практике увидеть:

* как построить микросервисную систему на Go;
* как использовать **gRPC** для синхронного взаимодействия между сервисами;
* как организовать **асинхронную обработку** через Apache Kafka;
* как разделить приём заказа и его фактическую обработку;
* как использовать **Redis** для быстрого хранения и получения результатов;
* как масштабировать отдельные компоненты системы независимо;
* как запускать инфраструктуру и сервисы через Docker Compose;
* как разделить окружения для разработки и production;
* как тестировать gRPC-сервисы;
* как подключать **Delve** для отладки Go-приложений внутри Docker.

Проект особенно полезен разработчикам, которые хотят перейти от разработки отдельных Go-сервисов к пониманию **полного взаимодействия нескольких компонентов распределённой системы**.

## Архитектура

Основной сценарий обработки заказа:

```text
Client
   │
   ▼
gRPC API
   │
   ▼
Kafka
   │
   ▼
Worker
   │
   ├── validation
   ├── business logic
   │
   ▼
Redis
   │
   ▼
CacheService
   │
   ▼
Client
```

### Компоненты

| Компонент          | Назначение                                             |
| ------------------ | ------------------------------------------------------ |
| **OrderService**   | Принимает заказ через gRPC и публикует событие в Kafka |
| **Kafka**          | Передаёт события между компонентами системы            |
| **Worker**         | Получает событие, выполняет валидацию и бизнес-логику  |
| **Redis**          | Хранит результат обработки для быстрого доступа        |
| **CacheService**   | Возвращает сохранённый результат через gRPC            |
| **Docker Compose** | Запускает сервисы и инфраструктуру                     |
| **Delve**          | Позволяет отлаживать Go-код внутри контейнера          |

## Почему здесь используется Kafka

Приём заказа и его обработка разделены.

Вместо того чтобы заставлять клиент ждать завершения всей бизнес-логики, `OrderService` передаёт событие в Kafka, после чего `Worker` обрабатывает его независимо.

Такой подход позволяет:

* отделить API от фоновой обработки;
* добавлять дополнительные consumers;
* независимо масштабировать workers;
* уменьшать связанность между компонентами;
* строить дальнейшие event-driven сценарии.

---

## Почему используется Redis

После обработки заказа результат сохраняется в Redis.

Это позволяет вынести быстрый доступ к результату в отдельный `CacheService` и не выполнять бизнес-логику повторно при каждом запросе.

В учебном проекте это также хороший пример того, как **кэш или быстрое key-value хранилище может быть встроено в микросервисную архитектуру**.

## Запуск

### Требования

* Go
* Docker
* Docker Compose
* `grpcurl` — для проверки gRPC API
* Delve — если требуется отладка

### Запуск окружения

Для разработки используется отдельный Docker Compose:

```bash
docker compose -f docker-compose.dev.yml up --build
```

Для production:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Проверить состояние контейнеров:

```bash
docker compose -f docker-compose.prod.yml ps
```

---

## Проверка gRPC

Получить список доступных сервисов:

```bash
grpcurl -plaintext 127.0.0.1:50051 list
```

Пример:

```text
grpc.reflection.v1.ServerReflection
grpc.reflection.v1alpha.ServerReflection
order.OrderService
```

## Отладка с Delve

Для запуска тестов в режиме отладки:

```bash
docker exec -it tests bash
dlv test ./tests \
  --headless \
  --listen=:40003 \
  --api-version=2 \
  --accept-multiclient \
  --log
```

Это позволяет подключить IDE к процессу внутри Docker-контейнера и исследовать выполнение Go-кода с breakpoint'ами.
